# book-blog — a book-notes blog for revision

## Goal
A personal Next.js blog where each book you read gets a section with detailed per-chapter study notes you can visit to revise. First book: *A Philosophy of Software Design, 2nd Ed.* (Ousterhout) — I'll write deep, section-by-section study notes for all 22 chapters plus its two appendices ("Summary of Design Principles", "Summary of Red Flags"), in my own words with short attributed quotes. Content is plain markdown + YAML frontmatter, editable both in your editor and in the browser (Keystatic). Includes dark mode, tags with cross-book concept pages, and client-side search. Reading-progress tracking is intentionally left out (you deselected it).

## Stack
- **Next.js 15** (App Router, TypeScript) + **Tailwind CSS v4** + `@tailwindcss/typography` for prose styling. Scaffold with `create-next-app` into `/home/mohammad/repos/book-blog` (empty today), git init, npm.
- **Markdown pipeline:** `gray-matter` (frontmatter) + `react-markdown` + `remark-gfm` + `rehype-slug` + `rehype-autolink-headings` + `rehype-highlight` (code highlighting). All rendering in server components with static generation (`generateStaticParams`), so it's fast and deployable anywhere.
- **Keystatic** (`@keystatic/core` + `@keystatic/next`) in local-repo mode at `/admin` — edits the same markdown files on disk. Verified: its slugs may contain `/` and paths support `**` globs, so nested per-book folders are supported with `format: { data: 'frontmatter' }` (fallback: its directory format, reader adapted accordingly).
- **next-themes** for dark mode; **fuse.js** + a build-time `public/search-index.json` for a ⌘K search dialog.

## Content layout (Obsidian-friendly, git-versioned)
```
content/
  books/aposd.md                      # book entry
  notes/aposd/                        # per-book folder of chapter notes
    01-introduction.md
    ...
    22-conclusion.md
    90-summary-of-design-principles.md
    91-summary-of-red-flags.md
public/covers/aposd.jpg               # cover extracted from the epub
```
Book frontmatter: `title, author, year, cover, status, started, summary, tags?`. Note frontmatter: `title, book (slug), chapter (number or null for front/back matter), date, summary (one-liner), tags`. Notes sort by chapter number; prev/next navigation derives from that.

## Pages
- `/` — hero, book cards (cover, status, one-line summary), recent notes, tag cloud.
- `/books/[book]` — book overview + full table of contents (chapters grouped: chapters / back matter).
- `/books/[book]/[note]` — note page: prose, tags, prev/next, back to TOC.
- `/tags` and `/tags/[tag]` — cross-book concept pages (starter taxonomy: complexity, deep-modules, information-hiding, strategic-vs-tactical, comments, naming, errors, consistency, performance, design-process …).
- `/admin` — Keystatic UI.
- Search: ⌘K dialog in the header over titles/summaries/tags/body text.

## Implementation steps
1. Verify Node version; scaffold Next.js app; install deps; git init + initial commit.
2. Build `lib/content.ts` (read/parse content, sorting, prev/next, tags, search index) and the Keystatic config + `/admin` route.
3. Build layout + all pages (header with search/theme toggle, typography polish).
4. Extract from the epub (python3, read-only on the source): cover → `public/covers/`, and per-chapter plain text into a git-ignored `.cache/` for note drafting.
5. **Generate the deep study notes:** spawn parallel agents over chapter-text batches; each note mirrors the chapter's numbered sections, states key ideas/principles, lists the chapter's red flags, quotes sparingly with attribution, and ends with an empty **"My takeaways"** section for you to fill. Tag from the starter taxonomy; write the two back-matter reference notes.
6. Search index generation (prebuild script), favicon, README with an "adding your next book" guide (scaffold convention + epub extraction script included for reuse).
7. Verify: `npm run build` clean; run dev server; click through pages in a browser; render key pages to PNG and run the visual-judge review; fix anything it flags.

## Out of scope (v1)
Reading-progress tracking, in-page comments, deployment setup — the architecture allows adding these later without content changes.
